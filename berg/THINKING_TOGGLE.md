# Как включать и выключать режим рассуждения у MiniMax и GLM

Короткая памятка. Главная ловушка: **у двух моделей разные имена параметра**, и перепутать их легко, потому что оба лежат внутри `chat_template_kwargs`.

## Параметры

**MiniMax M3** — ключ `thinking_mode`, три значения:

```python
extra_body={"chat_template_kwargs": {"thinking_mode": "enabled"}}    # думает всегда
extra_body={"chat_template_kwargs": {"thinking_mode": "disabled"}}   # не думает
extra_body={"chat_template_kwargs": {"thinking_mode": "adaptive"}}   # решает сам
```

Если параметр **не передать вообще**, включается `adaptive`, то есть модель сама решает на каждом ходу, думать ли. Это не является определённым условием эксперимента: получится смесь думающих и недумающих ответов. Для плеч тумблера всегда задавайте режим явно, включая плечо «с рассуждением».

**GLM-5.2** — ключ `enable_thinking`, булев:

```python
extra_body={"chat_template_kwargs": {"enable_thinking": True}}    # думает
extra_body={"chat_template_kwargs": {"enable_thinking": False}}   # не думает
```

**Qwen3** — тоже `enable_thinking`, как у GLM.

## Где лежит GLM

GLM-5.2 обслуживается только в регионе **uk-south1**. Если обратиться к нему через обычный `api.studio.nebius.com`, запрос не вернёт ошибку, а **зависнет** — модель числится в каталоге, но в вашем регионе не обслуживается. Нужен региональный адрес:

```
https://api.tokenfactory.uk-south1.nebius.com/v1/
```

Ключ тот же, `NEBIUS_API_KEY`. В нашем коде это уже прописано, GLM ходит через провайдера `nebius-uk`.

## Как проверить, что режим реально переключился

Смотреть на длину ответа **бесполезно**. Qwen выдаёт рассуждение прямо в тексте тегами `<think>`, а GLM и MiniMax выносят его в **отдельное поле** `reasoning` (в старых сборках `reasoning_content`), поэтому `content` выглядит одинаково в обоих режимах.

Правильные признаки — поле `reasoning` и расход токенов:

```python
msg = response.choices[0].message
reasoning = getattr(msg, "reasoning", None) or getattr(msg, "reasoning_content", "")
print(len(reasoning or ""), response.usage.completion_tokens)
```

Как выглядит рабочий тумблер (наши замеры):

| Модель | рассуждение вкл → выкл | токены вкл → выкл |
|---|---|---|
| MiniMax M3 | 3590 → 0 | 1209 → 609 |
| GLM-5.2 | 4626 → 0 | 1200 → 547 |
| Qwen3-32B | теги `<think>` есть → нет | 1200 → 823 |

Готовый скрипт для проверки: `python3 diag_sweep.py MiniMaxAI/MiniMax-M3`

## Три грабли, на которых мы уже потеряли время

**Неверный ключ не игнорируется, а меняет поведение.** Если передать MiniMax ключ `enable_thinking` (правильный для GLM, но не для MiniMax), рассуждение не выключится, а станет **длиннее** — 5097 символов против 3590 в дефолте. Флаг попадает в шаблон и портит рендеринг промпта. Поэтому режим всегда проверяйте замером, а не доверием к документации.

**Вендорский формат через Nebius не работает.** В документации MiniMax встречается `thinking: {"type": "disabled"}` — это формат их **собственного** API. Nebius такие поля молча выбрасывает, ошибки не будет, режим не переключится. Через Nebius работает только `chat_template_kwargs`.

**Бюджет токенов должен быть одинаковым в обоих плечах.** Если у думающего плеча `max_tokens=3000`, а у недумающего 1500, разница между ними будет включать усечение ответов, а не только режим. Мы на этом получили ложную значимость. Ставьте одинаковый лимит, ориентир — 3000.

## Запуск в нашем коде

```bash
cd berg
for m in minimax-m3-think minimax-m3-nothink glm-5.2-think glm-5.2-nothink; do
  MODELS="$m" N=100 MAX_TOKENS=3000 PYTHONUNBUFFERED=1 \
    nohup python3 run_full_cycle.py > "log_$m.log" 2>&1 &
done
```

Один процесс на модель. Два процесса на один файл дадут дубликаты, потому что оба при старте прочитают одинаковый список готовых диад.
